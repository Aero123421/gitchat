# 仕組み

[English](how-it-works.md)

gitchat は、ChatGPT・Claude・Gemini 上の会話を **自動ステージ → コミット → プッシュ** という git と同じ流れで、あなた自身の GitHub リポジトリに Markdown ファイルとして保存します。

## アーキテクチャの概要

gitchat は Manifest V3 対応の Chrome 拡張機能であり、各パートは型付きのメッセージプロトコル（`src/shared/protocol.ts`）を通じてのみ通信します。

```text
チャットページの DOM ──adapter──► CapturedMessage[] ──► ChatSnapshot ──request('chat/snapshot')──► background
                                                                                          │
            widget ◄──BackgroundEvent{status}── EVENTS_PORT ◄── stage (前回コミットとの差分) ┘
                                                              commit → ローカルコミット (IndexedDB)
                                                              push   → GitHub Git Data API (fast-forward のみ)
```

| パート | 実行環境 | 役割 |
| --- | --- | --- |
| `src/content/` | チャットページ（`chatgpt.com`, `claude.ai`, `gemini.google.com`） | サイトアダプタ、DOM から Markdown への変換、AI の状態監視、全文取り込み（init）、Shadow DOM ウィジェット（`<gitchat-ui>`）の表示 |
| `src/frame/` | 可視化用 iframe（`*.claudeusercontent.com`, `*.web-sandbox.oaiusercontent.com`, `*.scf.usercontent.goog`） | トップレベルのチャットページからの要求に応じて、レンダリング済みの可視化 HTML をシリアライズして返す |
| `src/background/` | Service Worker | GitHub 認証および Git Data API クライアント、ローカル DB（IndexedDB）、ステージング、ローカルコミット、マルチデバイス同期エンジン、Markdown ファイルの生成 |
| `src/popup/` | ツールバーのポップアップ | 現在のチャットの状態表示、コミットグラフ、クイック操作 |
| `src/options/` | 設定ページ | 初回セットアップウィザードおよび各種設定セクション |
| `src/content/ui/` | コンテンツスクリプト、設定プレビュー、プレイグラウンド | フレームワーク非依存の ES モジュール UI キット（ガラス表現、スプリング物理演算、3 種類のウィジェット、パネル） |

## チャットの追跡開始（init）

すべての会話が自動的に保存されるわけではありません。チャットは、ウィジェットの下（またはツールバーのポップアップ）にある **このチャットの保存を始める** をクリックするか、別の端末ですでに同じチャットがリポジトリに保存されていることが確認されるまで、**未追跡（untracked）** のままです。また、一時チャット（ChatGPT の `?temporary-chat=true`）は永続的なチャット ID を持たないため保存されません。

3 つのサービスはいずれも、長い会話では過去のメッセージを遅延読み込みし、多くの場合 DOM を仮想化（画面付近のメッセージのみを DOM に保持）しています。

- **ChatGPT**: 会話リストが仮想化されており（DOM 上には約 11 ターンのみ保持）、上端に到達するたび過去ログが 5 ターンずつ読み込まれ、スクロール位置が再調整されます。
- **Claude**: 会話リストが仮想化されており（DOM 上には約 20 行のみ保持）、上端で 32 行ずつ過去ログが読み込まれます。最初のターンには `aria-posinset="1"` が付与されます。
- **Gemini**: まず直近の 10 ターンが読み込まれ、`infinite-scroller.chat-history` が上端に達するたび 10 ターンずつ追加読み込みされます。画面外のターンには `content-visibility: auto` が適用されます。

保存を開始すると、**init** は次の 2 段階で会話全体を取り込みます。

1. **過去メッセージの読み込み（Loading）**: 現在の下端からのスクロール位置を記録したうえで、会話のスクロール領域を繰り返し一番上までスクロールさせます。メッセージ数・リストの高さ・スクロール位置が変化せず、読み込み中の表示もない状態がサイトごとの待機時間（`topQuietMs`）続くまで待機します。サイトによってはバッチを読み込むたびに行番号を振り直すため、「先頭」を示す目印だけでは判断しません。この間、進捗は読み込まれたメッセージ数（`↑ N`）として表示されます。10 分以内に履歴を読み込みきれなかった場合は、チャットの一部だけを保存するのではなく、エラーとして中止します。
2. **先頭から末尾までの読み取り（Reading）**: スクロール領域の先頭から末尾まで段階的にスクロールしながら、各位置で表示されているメッセージを読み取り、安定したメッセージ ID をキーとして会話順に統合（`OrderedMessages`）します。スクロールしながら収集するため、画面外の要素が DOM から消える仮想化リストでも漏れなく全文を取得でき、可視化もページから消える前に各段階で保存します。Gemini は読み込んだメッセージをすべてページ内に保持するため、1 回でまとめて読み取ります。進捗は `0%` から `100%` のパーセンテージで表示されます。

読み取りが終わった時点で AI がまだ回答中の場合は、回答が終わるのを待ってから会話の末尾をもう一度読み取ります。質問だけが回答なしで保存されることはありません。そのうえで完全なスナップショット（`complete: true`）をバックグラウンドへ送ります。回答を 1 つも含まないスナップショットは拒否されます。init はウィジェット下の **キャンセル** ボタンからいつでも中断でき、どちらの場合も元のスクロール位置に戻ります。同じチャットの init を同時に実行できるのは 1 つのタブだけです。3 つのサイトすべての 34〜40 ターンの実チャットで検証済みで、所要時間は約 4〜11 秒です。

## ステージ・コミット・プッシュ

### ステージング（Staging）

追跡中のチャットを開いている間、`AiObserver` がページ上の AI の状態変化（`idle` → `thinking` → `streaming` → `idle`）を監視します。

- **`sent` スナップショット**: プロンプトを送信して AI が `idle` から `thinking` または `streaming` に変わった時点で表示中のメッセージを取り込み、送信したメッセージがすぐにウィジェット上でステージ状態として反映されます。
- **`answered` スナップショット**: AI のストリーミング出力が終わり、サイトごとの待機時間（`doneQuietMs`、回答終了直後の状態チラつきによる誤検知を防ぐための時間）にわたって落ち着いた時点で `answered` スナップショットを送ります。

通常時のスナップショット（`complete: false`）は、IndexedDB 内の既存メッセージリストに対する **upsert（更新・追加）** として適用されます。同じ ID のメッセージは更新、新しい ID のメッセージは順番どおりに追加され、仮想化リストによって画面外に外れただけのメッセージはそのまま保持されます。会話の末尾まで写したスナップショットに、既知のメッセージより後ろの新しい ID が含まれる場合（プロンプトの編集や回答の再生成はこの形になります）は、そのメッセージ以降をスナップショットの内容に合わせ、ページから消えたターンを削除します（このタブで表示され得たターンに限ります。別の端末から届いたメッセージや、別のタブが後から読み取ったメッセージは残ります）。以前に読み取ったときとまったく同じ内容のメッセージは保存済みの内容を保つため、変化のないページを読み直しても、別の端末から取り込んだ編集が元に戻ることはありません。保存済みの内容と安全に照合できないスナップショット（最初のプロンプトを編集したときのように共通のメッセージが一つもない場合や、会話の末尾が短くなった場合）は適用せず、追跡開始時と同じ方法で会話全体を自動的に読み直します。init による完全スナップショット（`complete: true`）は、その最初のメッセージ以降についての正となります。リスト全体を置き換えるのは、取り込みが会話の先頭から始まっていると確認できた場合（会話全体が画面に収まっていた場合）だけで、それ以外は保存済みの古いメッセージを残します（古い履歴が読み込まれていなかっただけかもしれないためです）。空のものや回答を含まないものは拒否されるため、ページの構造変化などで読み取りに失敗しても保存済みのデータは消えません。スナップショットはページを読み取った順に適用され、遅れて届いた古いものは無視されます。

追跡中のチャットを開いたとき（拡張機能が再接続したときも含む）は、ページが落ち着くのを待ってから読み取ります。閉じたタブなど、gitchat が見ていない間に終わった回答もステージされます。**コミット** と **プッシュ** は、実行の直前にもう一度ページを読み取ります。

バックグラウンドは現在のメッセージ一覧と前回コミット時点のメッセージ一覧を「メッセージ ID」と「空白正規化済みの本文ハッシュ」で比較し、差分を **ステージ済み（staged）** として算出します。

### コミット（Commit）

コミットを実行すると、ステージされている変更から `LocalCommit` レコード（`{id, key, seq, message, n, createdAt, doc, pushed: false}`）を生成し、IndexedDB に保存します。

- コミットメッセージは `<service>: <チャットタイトル> (+<変更件数>)`（例: `claude: State design (+2)`）の形式になります。
- プッシュするまでの間に、1 つまたは複数のチャットで複数のローカルコミットを貯めておくことができます。
- **自動コミット** がオンの場合、コミットは `answered` スナップショット（AI の回答完了時）でのみ自動実行されます。`sent`（質問送信直後）や回答の途中では実行されないため、質問と回答が別々のコミットに分断されることはありません。

### プッシュ（Push）

プッシュを実行すると、すべてのチャットで未プッシュになっているローカルコミットを通し番号順に GitHub Git Data API で送信します。

1. 現在のチャットにステージ済み（未コミット）の変更がある場合、**プッシュ** を押すとまずそれが自動でコミットされるため、ステージ中の変更が取り残されることはありません。
2. 未プッシュの各コミットについて、チャットの Markdown ファイルと添付アセットの Blob を作成し、現在のブランチの Tree の上に新しい Git Tree と Git Commit を作成します。
3. 最後にブランチの参照（`refs/heads/<branch>`）を `force: false`（fast-forward のみ）で更新します。

### 自動コミット・自動プッシュのルール

- **自動プッシュ** をオンにすると、**自動コミット** も自動的にオンになります（コミットが存在して初めてプッシュできるため）。
- **自動コミット** をオフにすると、**自動プッシュ** も自動的にオフになります。
- **自動コミット** がオンのとき、ウィジェットとポップアップから手動の **コミット** ボタンは消えます。
- **自動プッシュ** がオンのとき、手動の **プッシュ** ボタンも消えます（ただし、直前のプッシュがエラーになった場合は、手動で再試行できるよう赤いプッシュボタンが表示されます）。
- 自動プッシュは連続するコミットをまとめるため短い待機時間（3 秒）をおいて実行されます。ネットワークエラーや GitHub のレート制限で失敗した場合は、`chrome.alarms` を使って指数バックオフ（最大 30 分、または GitHub が返すリセット時刻）で自動的に再試行します。待ち時間は保存されるため、Chrome が拡張機能のバックグラウンドを再起動しても早まりません。自分で **プッシュ** を押した場合は待たずに送ります。

## リポジトリ構成とファイル形式

リポジトリのルート直下に、サービス別の 3 つのフォルダが作られます。

```text
README.md
chatgpt/2026-11-09-state-design--a1b2c3d4.md
claude/2026-11-09-react-hooks--9f8e7d6c.md
claude/2026-11-09-react-hooks--9f8e7d6c.assets/viz-1.html
gemini/2026-11-09-query-planner--7c6b5a4d.md
```

### ファイル名の規則

各チャットのファイルパスは次の形式で決まります。

```text
<service>/<YYYY-MM-DD>-<title-slug>--<id8>.md
```

- `<service>`: `chatgpt`、`claude`、`gemini` のいずれか。
- `<YYYY-MM-DD>`: 初回取り込み時の端末ローカルタイムゾーンでの日付。
- `<title-slug>`: 会話タイトルを NFKC 正規化・小文字化したスラッグ（日本語を含むあらゆる言語の文字・数字を保持し、最大 48 文字。空の場合は `chat`）。
- `<id8>`: チャット ID の先頭 8 文字（ファイル名に使える文字のみ。同じフォルダの別のチャットがすでにその 8 文字を使っている場合は、さらに長くなります）。

ファイル名は **初回作成時に固定** されます。あとからチャット上でタイトルを変更しても、ファイル内の YAML フロントマターの `title` と `# 見出し` が更新されるだけで、ファイル名自体は移動・変更されません。別の端末は `<service>/` 内の `--<id8>.md` という末尾で同じチャットのファイルを見つけ、フロントマターのサービス名とチャット ID を確認してから使います。

### Markdown のフォーマット

```markdown
---
gitchat: 1
service: claude
id: "9f8e7d6c-1234-5678-9abc-def012345678"
url: "https://claude.ai/chat/9f8e7d6c-1234-5678-9abc-def012345678"
title: "State design"
created: 2026-11-09T09:12:00.000Z
captured: 2026-11-09T10:40:00.000Z
messages: 14
---

# State design

## User
<!-- gitchat:message id="..." length="..." -->

状態遷移はどのように設計すべきでしょうか？

## Assistant
<!-- gitchat:message id="..." length="..." -->

次のような状態遷移表にすると整理しやすくなります...
```

各ロール見出しの直下にある `<!-- gitchat:message -->` コメントには、メッセージの安定 ID と本文の長さが記録されます。ID により、別の端末が GitHub からこのファイルを読み込んだ際にも、どのメッセージまでコミット済みかを正確に判別して続きからステージできます。長さにより、gitchat のファイルそのものを引用したメッセージや、コードブロック内に `## Assistant` を含むメッセージも、1 つのメッセージとして正しく読み戻せます。

## 取り込まれる内容

### Markdown への変換

各チャットサービスは Markdown を独自の HTML にレンダリングしています。gitchat はその DOM を解析し、AI エージェントや人間がそのまま読めるクリーンな Markdown に戻します（`src/content/capture/markdown.ts`）。

- **テキストとインライン装飾**: 段落、改行、太字（`**...**`）、斜体（`*...*`）、取り消し線（`~~...~~`）、インラインコード（コード内にバッククォートが含まれる場合は自動で外側のバッククォート数を増やしてエスケープ）、上付き文字（`<sup>`）、下付き文字（`<sub>`）。
- **見出し**: `<h1>`〜`<h6>`。サイト側が見出しレベルを 1 段ずらして描画している場合（ChatGPT の新 UI や Claude では `##` が `<h3>` として描画されます）は元の見出しレベルに補正します。
- **リストと引用**: 番号付きリスト（`1.`）・箇条書きリスト（`-`）のネストとインデント、複数段落を含むリスト項目の空行維持、`>` による引用ブロック。
- **表（テーブル）**: GitHub Flavored Markdown のテーブル記法に変換します。サイト側が列の揃え位置（中央・右揃え・左揃え）を属性やスタイルに保持している場合は `:---:`・`---:`・`---` として反映します。
- **コードブロック**: 言語識別子付きのフェンスドコードブロックに変換します（CodeMirror の `data-language`、`language-*` クラス、ヘッダーの言語ラベルから取得）。ChatGPT のコードブロックのようにページが元のソースを別に保持している場合は、そこからそのまま取得します。インラインコード（ChatGPT の inline-code の span を含む）もコードとして保存します。
- **元の TeX 記法での数式**: KaTeX の `<annotation encoding="application/x-tex">`、MathJax の `<mjx-container>`、MathML の `alttext`、またはサイト固有の数式属性（`data-math`, `data-latex`, `data-tex`）から TeX ソースを抽出し、インライン数式は `$...$`、ディスプレイ数式は `$$...$$` に復元します。
- **折りたたみブロック**: メッセージ本文内に `<details>` / `<summary>` がある場合はそのまま出力します。

### インタラクティブな可視化（アーティファクト・Canvas）

Claude のアーティファクト（`*.claudeusercontent.com`）、ChatGPT のインライン可視化（`*.web-sandbox.oaiusercontent.com`）、Gemini の Canvas プレビュー（`*.scf.usercontent.goog`）は、クロスオリジンのサンドボックス iframe 内で描画されます。

設定の **可視化を保存** がオン（初期値）になっており、取り込み時にその可視化が画面上に表示されている場合、次の手順で保存されます（プレビューパネルは、どのメッセージのものか確かな場合だけ保存します。クリックしたカード、または Claude で現在のカードとして示されているカードです）。

1. コンテンツスクリプトが対象の iframe に対して `{gitchat: 1, type: 'frame/serialize', nonce}` メッセージを送ります。
2. iframe 内の `src/frame/index.ts` は、送信元が許可されたオリジン（`https://claude.ai`、`https://chatgpt.com`、`https://gemini.google.com`）の `window.top` であることを検証したうえで、`<!doctype html>\n` + `document.documentElement.outerHTML` を返します。
3. バックグラウンドがその HTML を `<チャットファイル名（.md なし）>.assets/<slug>.html` として保存し、Markdown 内のアーティファクト表記を相対リンク（`> **Artifact:** [Title](<chat>.assets/<slug>.html)`）に書き換えます。

### 既知の制限事項

- **Web 検索の引用 URL**: ChatGPT と Gemini は、Web 検索の引用ピルの URL をページの DOM 内に直接出力しません（ポップオーバー操作時にのみ表示・取得されます）。そのため、gitchat はページに表示されているものを残します。ChatGPT は角括弧のソース名（`[ソース名]`）、Gemini は番号付きの引用マーカー（`[1]`）です。
- **レンダリング済み HTML としての保存**: Gemini Canvas と ChatGPT のインライン可視化は、元のソースファイルではなくサンドボックス iframe 内のレンダリング済み HTML として保存されます。
- **取り込み時に画面上に開いている必要があること**: アーティファクトや可視化は、取り込みが実行される時点で iframe が画面上に存在し描画されている場合にのみ HTML として保存されます。
- **編集・再生成された会話ブランチ**: メッセージを編集したり回答を再生成したりして分岐がある会話では、その時点で画面に表示されているブランチのみが保存されます。編集や再生成は自動で反映され、ページが保存済みの内容と合わなくなった場合（最初のプロンプトを編集した場合など）は会話全体を自動で読み直します。ブランチを切り替えたあとも保存内容がおかしいときは、ツールバーのポップアップで **チャット全体を読み直す**（↻）をクリックしてください。

## 複数端末での同期（マルチデバイス）

gitchat は、複数のパソコンから同じ GitHub リポジトリへプッシュしても手動でのコンフリクト解決が一切発生しないように設計されています。

- **リモートブランチが正（fast-forward のみ）**: プッシュは常に `force: false` で行われ、強制プッシュ（force push）で履歴を上書きすることは決してありません。
- **non-fast-forward 時の自動リプレイ**: 端末 B に未プッシュのコミットがある間に端末 A が先にプッシュしていた場合、端末 B のプッシュは non-fast-forward として拒否されます。すると gitchat は自動的にリモートの最新 `HEAD` を読み直し、端末 B のローカルコミットを最新ツリーの上にリプレイ（リベース）して再試行します（最大 4 回）。
- **同じチャットが両方の端末で更新された場合（メッセージ単位で統合）**: 端末 B が最後に同期した時点以降にリモート側のチャットファイルが変更されていた場合、gitchat はその同期時点の内容を基準に、メッセージ単位で両方を統合します。片方の端末だけが変えたメッセージはその変更を採用し、両方が変えたメッセージは新しい取り込み（YAML フロントマターの `captured`、同時の場合は `messages` の件数）を採用します。片方だけが追加したメッセージはそのまま残ります。ローカルのコミットが追加する内容がすでにリモート側にすべて含まれている場合、そのコミットはスキップ（superseded）されます。端末 B はその後、プッシュ中に作ったコミットも保ったまま統合後の内容から作業を続けるため、後のプッシュで端末 A にしかなかったメッセージが消えることはありません。以前の版は git の履歴に残ります。
- **他の端末で保存されたチャットの自動引き継ぎ**: 端末 A で保存・プッシュ済みのチャットを端末 B で開くと、gitchat はリモートツリーから `--<id8>.md` で一致するファイルを探し出し、フロントマターのチャット ID を確認し、メッセージ一覧を読み込んで（`adoptRemote`）、端末 B でもそのまま追跡状態を引き継ぎます。可視化ファイルも一緒にダウンロードし、ダウンロードに失敗した場合はファイルを欠いたまま引き継がず、次に開いたときに改めて引き継ぎます。すでにファイルがあるチャットの保存を開始した場合も同様で、2 つの取り込みのうち新しい方が優先されます。新しい方に閉じたカードしか写っていない場合も、保存済みの可視化はそのまま残ります。
- **保存先リポジトリの変更**: コミット、ファイルのパス、同期の状態は 1 つのリポジトリに属します。別のリポジトリに切り替えると、元のリポジトリにプッシュしていなかったコミットは破棄され（チャットの会話そのものには影響しません）、追跡中のチャットは可視化のファイルも含めて、すべて新しいリポジトリ向けに全体がステージされます。プッシュ中の場合は、それが終わってから切り替わります。
- **共有インデックスファイルを持たない構造**: 各チャットは自身の `<service>/<file>.md`（および `<file>.assets/`）にのみ書き込むため、異なるチャット間のコミットが競合することはありません。

## ページ上のウィジェットとパネル

ウィジェットはページ右端の独立した `<gitchat-ui>` Shadow DOM 内に描画され、ページのライト／ダークテーマに自動で追従します。また、右端に沿って上下の好きな位置へドラッグして配置できます。

| スタイル | 表現と操作 |
| --- | --- |
| **キャラ (Creature・標準)** | すりガラス調の小さなキャラクターです。周りを回る水滴が未コミットのステージ済みメッセージ、体内の青い粒が未プッシュのコミットを表します。入力欄へのタイピングを目で追い、スクロール時には重みをもって遅れてついていき、AI が考えている間は首をかしげ、回答がストリーミングされている間は体表に新しい水滴が育って完了時に軌道へ離れます。コミットすると水滴を飲み込み、プッシュすると青い粒が上へ飛び立ちます。 |
| **ライン (Line)** | 画面右端に配置される細いガラスのカプセルで、コミット履歴をチャットと同じく上から下へ時系列（上が古いコミット、下が新しいコミット、一番下の白いリングが未コミット作業）のドットとして常時表示します。細い横線がリモートの `origin`（線より上は GitHub にプッシュ済み）を表します。カーソルを合わせるとカプセルが広がってドットが拡大され、リングをクリックするとコミット、origin の横線をクリックするとプッシュ、それ以外の場所をクリックするとパネルが開きます。 |
| **ドット (Dot)** | コンパクトな円形のガラスダイヤルです。中央の数字が未コミットのメッセージ数（変更がないときは小さな中心点）、外周リング上の青い目盛りが 12 時方向から順に並ぶ未プッシュのコミットを表します。プッシュが完了すると、目盛りが 12 時方向へ戻って消えます。 |

どのウィジェットでも、カーソルを合わせると下に丸い操作ボタン（未追跡なら **このチャットの保存を始める**、init 中なら **キャンセル**、追跡中なら **コミット** と **プッシュ**）が現れます。追跡中のウィジェットをクリックするとガラスパネルが開き、コミットグラフ、操作バー（コミット・プッシュ・GitHub リンクのコピー・設定）、および **自動コミット**・**自動プッシュ** のスイッチを操作できます。

ウィジェットはキーボードでも操作できます。<kbd>Tab</kbd> でフォーカスするとボタンが現れ、<kbd>Enter</kbd> でパネルが開き、<kbd>Esc</kbd> で閉じます。描画は動きがあるときだけ行われ（キャラは待機中、低いフレームレートで呼吸します）、OS で動きを減らす設定（macOS の **視差効果を減らす**、Windows の **アニメーション効果** のオフ）にしている場合は、状態の変化以外では動きません。
