# トラブルシューティング

[English](troubleshooting.md)

gitchat のセットアップや利用中によくある質問と、エラーメッセージへの対処方法をまとめています。

## GitHub との接続・サインイン

### 「GitHub でサインイン」を押すと個人アクセストークンの画面に切り替わる

インストールしたビルドに組み込みの OAuth クライアント ID が設定されていない場合（または設定された OAuth アプリで Device Flow が無効になっている場合）、gitchat は自動的に **個人アクセストークン** の入力画面へ切り替わります。

- **推奨される対処方法**: **GitHub でトークンを作成** をクリックし、チャット保存用リポジトリに対して **Contents: Read and write** と **Metadata: Read** を許可した fine-grained 個人アクセストークンを作成して貼り付けてください。
- **別の方法（フォークや自前のアプリを使う場合）**: 自分で GitHub App または OAuth App を作成し、GitHub 側の設定で **Device Flow** を有効にしたうえで、そのクライアント ID を **設定 → 詳細 → GitHub OAuth クライアント ID** に入力してください。

### 「このトークンは使えませんでした」または「このアカウントにはそのリポジトリへの書き込み権限がありません」と表示される

[GitHub の個人アクセストークン設定ページ](https://github.com/settings/tokens) で次の点を確認してください。

1. トークンの有効期限が切れていないか、失効していないか。
2. **Resource owner** が保存先リポジトリを所有するアカウント（または Organization）になっているか。
3. **Repository access** に保存先リポジトリが含まれているか。
4. **Repository permissions** で **Contents** が **Read and write**、**Metadata** が **Read** に設定されているか。

拡張機能を削除しなくても、戻って別のトークンを使えます。リポジトリのステップの **トークンが違いますか？別のトークンを使う**、または GitHub のステップの **別のトークンを使う** です。

### 「コードの有効期限が切れました。もう一度お試しください。」と表示される

OAuth デバイスコードの有効期限は 15 分です。もう一度サインインを開始し、カウントダウンが終わる前に GitHub 上で承認してください。

## リポジトリの選択・作成

### 「このリポジトリには gitchat 以外のファイルがあります」と表示される

既存のコード用リポジトリなどに誤って書き込むのを防ぐため、gitchat は「空のリポジトリ」または「すでに gitchat が管理しているリポジトリ（`README.md` に `<!-- gitchat -->` が含まれているか、`chatgpt/`・`claude/`・`gemini/` 内に `.md` ファイルが存在するもの）」以外を拒否します。

空のリポジトリを選ぶか、gitchat の「新しく作る」から新しい非公開リポジトリを作成してください。

### fine-grained トークンを使うと「新しく作る」でリポジトリを作成できない

**Only select repositories**（特定のリポジトリのみ）に限定した fine-grained トークンには、GitHub API で新しいリポジトリを作成する権限がありません。1 つのリポジトリに限定したトークンを使う場合は、次の手順で行ってください。

1. 先に GitHub 上で空の非公開リポジトリを作成します（gitchat の **GitHub でリポジトリを作成** ボタンから、入力済みの作成画面を開けます。README・`.gitignore`・ライセンスは追加しないでください）。
2. そのリポジトリ 1 つだけを対象に、**Contents: Read and write** と **Metadata: Read** を付与した fine-grained トークンを作成します。
3. gitchat のリポジトリ選択ステップで **既存のリポジトリ**（トークンで接続した場合は最初からこちらが開きます）を開き、手順 1 で作成したリポジトリを選択します。

### 作成したリポジトリが一覧に出てこない

gitchat は、接続したアカウント（またはトークン）でプッシュできるリポジトリを一覧に表示します。一覧に表示されない場合は次を確認してください。

- 検索欄にリポジトリの正式名（`owner/name`）を入力し、**owner/name を確認** をクリックしてから **使う** をクリックします。
- fine-grained トークンの **Repository access** にそのリポジトリが含まれており、**Contents: Read and write** が付与されていること。
- 読み取り専用（Read-only）のリポジトリはプッシュできないため一覧から除外されます。

## ウィジェットとチャットの認識

### チャットページを開いても右端にウィジェットが表示されない

次の 4 点を確認してください。

1. **会話に固定の URL が割り当てられているか**:
   - 新規チャットの最初のメッセージを送る前は URL に会話 ID が含まれないため、ウィジェットはまだ表示されません。
   - ChatGPT で最初のメッセージを送った直後は、一時的な `/c/local-chatgpt:<uuid>` という URL になることがあり、永続的な `/c/<uuid>` に切り替わるまで待機します。
   - 対応する URL パスは `chatgpt.com/c/<uuid>`、`claude.ai/chat/<uuid>`、`gemini.google.com/app/<id>`（または `/gem/<gem>/<id>`）、`grok.com/c/<uuid>` です。Grok のプライベートチャットは `grok.com/` のままなので保存されません。
   - Gemini は 2 つ目の Google アカウント（`/u/<n>/app/<id>` または `/u/<n>/gem/<gem>/<id>`）でも同じチャットとして保存できます。保存されるリンクからはアカウントのスロットと、`?authuser` や `?hl` などのクエリを除きます。
2. **一時チャットではないか**: ChatGPT の一時チャット（`?temporary-chat=true`）は保存しない設計のため、ウィジェットは表示されません。
3. **設定でサービスが有効になっているか**: **設定 → 動作 → サービス** を開き、**ChatGPT**・**Claude**・**Gemini**・**Grok** がオンになっているか確認してください。
4. **拡張機能のインストールや再読み込みの前から開いていたタブではないか**: 拡張機能を有効化する前から開いていたタブにはコンテンツスクリプトが注入されません。チャットのタブを一度リロードしてください。

### ウィジェットにコミットボタンやプッシュボタンが表示されない

自動実行がオンになっている操作のボタンは、ウィジェットおよびポップアップから非表示になります。

- **自動コミット** がオンのとき: **コミット** ボタンは表示されません。
- **自動プッシュ** がオンのとき: **コミット** と **プッシュ** の両方のボタンが非表示になります（ただし、プッシュがエラーになった場合は再試行できるよう赤いプッシュボタンが現れます）。

ウィジェットをクリックしてパネルを開くか、**設定 → 動作** から **自動コミット**・**自動プッシュ** を切り替えられます。

## 取り込みと全文の初回取り込み（init）

### 長いチャットで「保存を始める（init）」に時間がかかる

ChatGPT・Claude・Gemini・Grok はいずれも過去のメッセージを少しずつ遅延読み込み（ChatGPT は 5 ターンずつ、Claude は 32 行ずつ、Gemini は 10 ターンずつ、Grok は直近約 50 件のあとに残り）し、読み込みのたびにスクロール位置を再調整します。**init** では過去ログが追加されなくなるまで繰り返し先頭へスクロールし、そこから上から下へ順番に読み取ることで仮想化リストの全文を取得します。

- 件数（`↑ N`）と読み取りパーセンテージ（`0–100%`）が進んでいる間は、そのタブを開いたままお待ちください。
- 34〜40 ターンの会話では通常 4〜11 秒ほどで完了しますが、数百ターンにおよぶ会話ではサイト側のサーバーからの読み込み待ちの分だけ時間がかかります。
- 途中で止めたい場合は、ウィジェット下の **キャンセル** ボタンでいつでも中断できます。

### 「The capture found no messages, so nothing was changed」と表示される

gitchat は保存済みデータを保護するため、取り込み結果が空だった場合は既存のメッセージを上書きせずエラーとして報告します。

1. ページの描画が完了していない場合は、タブをリロードして会話が表示されてからもう一度試してください。
2. チャットサイト側の HTML 更新によってセレクタが一致しなくなった場合は、[Site adapters](site-adapters.md)（英語）を参照するか、GitHub の Issue でお知らせください。

### 「チャット全体を読み込めなかったため、保存しませんでした」

init は履歴をすべて読み込めた場合にだけチャットを保存します。このメッセージは、サイトが 10 分以上過去メッセージを読み込み続けたか、読み込みが落ち着かなかったことを示します。タブを開いたまま表示し、接続を確認してから、もう一度始めてください。非常に長いチャットを低速な回線で読み込む場合は、2 回目で完了することもあります。

### 「一部のメッセージを読み取れなかったため、保存しませんでした」

長いチャットでは、サイトは会話の一部だけをページに置き、残りはスクロールに合わせて描画します。gitchat は保存する前に、すべてのメッセージ（Claude では番号付きのすべての行）を読み取れたかを確認します。このメッセージは、スクロール中に一部の行が表示されなかったことを示します。多くの場合、ページの描画が遅かったためです。タブを表示したまま、もう一度始めてください。

### 「最新のメッセージを読み取れなかったため、コミットもプッシュもしませんでした」

コミットとプッシュは、最新の回答を含めるために実行の直前にもう一度ページを読み取ります。その読み取りに失敗した場合は、古い状態を保存しないよう中止します。ページの読み込みが終わってからもう一度お試しください。タブの再読み込みも有効です。

### 「チャットの読み取りが先に進まなくなったため、保存しませんでした」

長いチャットを読み取るとき、gitchat はページをスクロールしながら読み進めます。25 秒間スクロールも新しいメッセージの表示もなければ、読み取りを止めます。チャットを少しスクロールするか、タブを再読み込みしてから、もう一度保存を始めてください。

### 「ページにまだ前のチャットが表示されていたため、保存しませんでした」

チャットを切り替えた直後は、ページにしばらく前の会話が表示されたままのことがあります。gitchat はそれを新しいチャットとして保存しません。新しいチャットの表示を最大 10 秒待ち、それでも表示されなければ止めます。チャットが読み込まれてから、もう一度保存を始めてください。

### 「回答の生成が続いています。終わってからもう一度保存を始めてください。」

保存されたチャットが質問だけで終わらないよう、init は生成中の回答が終わるのを待ちます。10 分以内に回答が終わらなかった場合、このメッセージで中止します。回答が終わってからもう一度始めてください。

### 「このチャットに回答が見つからなかったため、保存しませんでした」

ページにあなたのメッセージは表示されていましたが、回答が見つかりませんでした。多くの場合はページの表示が終わっていなかったためです。ページを再読み込みしてもう一度お試しください。繰り返し起きる場合は、サイトの HTML が変わった可能性があります。Issue を作成してください（[サイトアダプタ](site-adapters.md) を参照）。

### インタラクティブな可視化（アーティファクト・Canvas・グラフ）が HTML ファイルとして保存されない

可視化が `<chat>.assets/<name>.html` として保存されるには、次の 2 つの条件を満たしている必要があります。

1. **設定 → 動作 → 取り込み** の **可視化を保存** がオンになっていること（初期値はオン）。
2. 取り込みが行われる時点で、その可視化の iframe（`*.claudeusercontent.com`, `*.web-sandbox.oaiusercontent.com`, `*.scf.usercontent.goog`）が **画面上に開かれて描画されていること**。特に Claude のアーティファクトは、回答完了時または init 実行時にサイドパネルで開いている必要があります。

なお、Gemini Canvas および ChatGPT のインライン可視化は、元のソースコードではなくレンダリング済みの HTML として保存されます。

### ChatGPT や Gemini の Web 検索の引用に URL が付かない

ChatGPT と Gemini は、Web 検索の引用リンクの URL をページの DOM 内に直接出力しないため（ピルにカーソルを合わせたり開いたりしたときにのみ表示されます）、gitchat では引用元のソース名のみを `[ソース名]` として保持します。

### メッセージを編集・再生成した会話の別ブランチが保存されない

プロンプトの編集や回答の再生成によって分岐がある会話では、ページ上に現在表示されているブランチのみが保存されます。編集や再生成は自動で反映され、ページが保存済みの内容と合わなくなった場合（最初のプロンプトを編集した場合など）は会話全体を自動で読み直します（ウィジェットに進捗が表示されます）。ブランチを切り替えたあとも保存内容がおかしいときは、ツールバーのポップアップで **チャット全体を読み直す**（↻）をクリックしてください。

## プッシュと複数端末での同期

### ネットワークエラーや GitHub の利用制限でプッシュに失敗した

コミットされた内容は端末内の IndexedDB に安全に保存されており、消えることはありません。

- ウィジェットまたはツールバーのポップアップから **プッシュ** を押すと手動で再試行できます。
- **自動プッシュ** がオンになっている場合は、`chrome.alarms` によって指数バックオフ（最大 30 分、または GitHub のレート制限リセット時刻まで待機）でバックグラウンド再試行が自動的にスケジュールされます。待ち時間は拡張機能のバックグラウンドが再起動しても保たれます。自分で **プッシュ** を押すとすぐに再試行します。

### 「gitchat のバックグラウンドが応答しません。もう一度お試しください。」と表示される

Chrome がアイドル状態の Manifest V3 Service Worker を一時停止したか、拡張機能が更新・再読み込みされた直後に発生することがあります。もう一度操作するか、拡張機能を再読み込みした場合はチャットのタブをリロードしてください。

### 別のパソコンからプッシュしたあと、手元のパソコンのコミットがスキップされた

2 台の端末で同じチャットを更新した場合、gitchat は最後に同期した版を基準に、両方の変更をメッセージ単位で統合します。ローカルのコミットが追加する内容がすでにリポジトリ側にすべて含まれている場合、そのコミットには送る内容が残っていないため、スキップ（superseded）されます。メッセージはファイルに含まれており、以前の版もリポジトリの `git log` に残っています。
