状態管理の設計

React の状態管理、どう設計するのがいい？規模は中くらいで、サーバーのデータが多め。

サーバーのデータが多いなら、まず「サーバー状態」と「UI 状態」を分けるのがおすすめです。

  • サーバー状態: TanStack Query などのキャッシュ層に任せる
  • UI 状態: コンポーネント内か、小さなストアで持つ
  • URL 状態: フィルタやタブは URL に載せる
const useFilters = create((set) => ({
  tab: 'all',
  setTab: (tab) => set({ tab }),
}));

const { data } = useQuery({
  queryKey: ['todos', tab],
  queryFn: () => fetchTodos(tab),
});

こうしておくと、再取得や重複排除をライブラリに任せられます。

再レンダリングのコストを式で表せる？

ざっくり言うと、更新 1 回あたりのコストは「再描画されるコンポーネントの数 × 1 つあたりの重さ」です。

C = Σi∈R ri · wi  ≈  |R| · w̄

ストアを細かく購読すれば R が小さくなり、メモ化すれば w が小さくなります。

なるほど。じゃあ移行の手順も教えて

段階的に進めるのが安全です。まずサーバー状態だけをキャッシュ層に移し、次に UI 状態を整理します。最後に Context を細かく分けて、不要な再描画を測定しながら減らしていきます。
